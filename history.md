## 0. Rules

1. **Never run the benchmark or `omlx serve` to verify.** Verification = §12 only.
2. Python ≥ 3.11. Allowed third-party deps: `rich`, `matplotlib`, `huggingface_hub`, `pyyaml`. Nothing else.

4. Never delete anything outside `~/.omlx-bench/base/<run_id>/` and `runs/<run_id>/cache/`.
5. All times in files: `time.time()` floats or ISO-8601 strings. All temperatures °C. All power W.
6. Every JSON file written by the tool contains `"schema": 2` at top level.
7. Keep `# noqa` comments and exception handling exactly as in the moved code.


Validation in `config.load_models(path) -> Config` (raise `ValueError` with the offending key path):
- `models.<name>`: required `repo` (str). Optional `color` (hex str), `settings` (dict, per-model oMLX settings).
- `profiles.<name>.server`: allowed keys only. Each key maps to a CLI flag (§4.2) or, when oMLX has no flag,
  to a `settings.json` path in the isolated base (§4.3). Unknown key → error. Allowed keys and types:
  `hot_cache_max_size` (str), `paged_ssd_cache_max_size` (str), `hot_cache_write_through` (bool),
  `initial_cache_blocks` (int), `no_cache` (bool), `hot_cache_only` (bool).
- `hot_cache_only: true` requires `hot_cache_max_size` ≠ `"0"` and `no_cache` not true; else error.
- `profiles.<name>.model_settings`: dict merged over `models.<name>.settings` (profile wins).
- Model name and profile name: regex `^[a-z0-9][a-z0-9-]*$`.
- `levels` items: positive int or the literal string `knee`.
- A model with no `color` gets one from a fixed 10-color cycle in `plots.py` by sorted-name index.

## 4. oMLX control (`omlx.py`)

### 4.1 Preflight (`omlx.preflight(port, api_key)`), called once before any server start
1. `ensure_omlx()` (moved as-is).
2. `free_port()` on `port` (moved as-is).
3. Read `~/.omlx/settings.json` → `server.port` (if present). `GET http://127.0.0.1:<that port>/v1/models` with 2 s
   timeout. Any HTTP response (incl. 401) → abort with
   `"oMLX app server is running on port N; quit oMLX.app before benchmarking"`. Connection error → continue.

### 4.2 `Server.start(model_dir, concurrency, profile, base_path, cache_dir, log_path)`
Command, in this order, flags only when the key is present in `profile.server`
(`hot_cache_only` has no flag; it is applied in §4.3):

```
omlx serve --model-dir <model_dir> --port <PORT> --base-path <base_path>
  --max-concurrent-requests <concurrency>
  --hot-cache-max-size <hot_cache_max_size>
  --paged-ssd-cache-dir <cache_dir>              # always, unless no_cache
  --paged-ssd-cache-max-size <paged_ssd_cache_max_size>
  --hot-cache-write-through                      # if true
  --initial-cache-blocks <initial_cache_blocks>
  --no-cache                                     # if true; then omit --paged-ssd-cache-*
  --api-key <api_key>                            # if api_key set
```

`wait_ready` unchanged (includes the 401/403 fast-fail).

### 4.3 Isolated base path (replaces all admin-API setting changes)
`omlx.prepare_base(run_id, cell_id, profile, model_dir_name, model_settings) -> Path`:
1. `base = ~/.omlx-bench/base/<run_id>/<cell_id>`; `shutil.rmtree(base, ignore_errors=True)`; `mkdir(parents=True)`.
2. `settings = json.load(~/.omlx/settings.json)`, or `{}` if missing. Set
   `settings.setdefault("cache", {})["hot_cache_only"] = bool(profile.server.get("hot_cache_only", False))`
   (always written, so the user's app value never leaks into a profile). Write
   `base/settings.json`.
3. `ms = json.load(~/.omlx/model_settings.json)`, or `{"version": 1, "models": {}}`.
   `ms["models"][model_dir_name] = {**ms["models"].get(model_dir_name, {}), **model_settings}`.
   Write `base/model_settings.json`.
4. Return `base`. `sweep.py` deletes it after the server of that cell stops (`finally`).

`model_dir_name` = `repo.split("/")[-1]` (same key oMLX uses; matches current `set_mtp` call).

Delete `Admin.set_mtp` and every call to it. Keep `Admin.login` only if §4.4 needs it.

### 4.4 Settings verification, after `wait_ready`
1. `Admin.login()`; `GET /admin/api/models/<model_dir_name>/settings`.
2. If 200 and JSON: for each key in `model_settings`, compare. Result
   `{"verified": true|false, "mismatch": {key: [wanted, got]}}`.
3. Otherwise: `{"verified": null, "reason": "HTTP <code>"}`.
4. Store in the cell record as `settings_check`. Mismatch → cell still runs; report shows `⚠ settings`.

### 4.5 Settings snapshot (once per run)
`omlx.snapshot_settings(model_dir_names) -> dict`: `settings.json` with the `auth` key removed entirely, plus
`model_settings.json["models"][name]` for each tested model. Stored in `run.json["omlx_settings"]`.

### 5.3 Cell spec (`plan.py`)
```json
{"id": "007_speed_mlx4_kv4_c4_t1", "stage": "speed", "model": "mlx4", "profile": "kv4",
 "workload": "ifbench|prefix", "c": 4, "trial": 1, "scored": false,
 "jobs": [["<pid>", <sample>], "..."]}
```
- `id` = `f"{i:03d}_{stage}_{model}_{profile}_c{c}_t{trial}"`, `i` = position after shuffle.
- Stage `quality`: one cell per (model, profile) pair, `c = --quality-c`, `trial = 0`, `scored = true`,
  `jobs` = every IFBench pid × `range(--samples)`, shuffled with `random.Random(seed)`.
  Skip the pair if the effective `model_settings` (model ∪ profile) equals one already planned for the same repo.
- Stage `speed`: model × profile × level × trial. `scored = false`. `jobs` = `max(--min-requests, c * --rounds)`
  IFBench pids drawn with `rng.sample` (without replacement, different per cell), sample index 0.
- Stage `cache`: model × profile × level × trial with `workload = "prefix"`, `jobs` per §7.3.
  `levels` entry `knee` is resolved when the stage is materialized (§6.1): `stats.throughput_knee` on the
  `speed` cells of `(model, "baseline")`; if none or no knee, use `2`. Deduplicate levels after resolution.
- Shuffle cells **within** a stage. Stages run in list order.
- `preset default` = one stage `speed` with `--profiles`/`--levels` from CLI, plus stage `quality` unless
  `--no-quality`, placed first.

### 5.4 Loading (`load_run(path) -> Run`)
- Load `run.json`; if missing or `schema != 2` → raise `ValueError("not a schema-2 run: <path>")`.
  Old-format runs (`plan.json`) are not supported.
- Cells = `cells/*.json`; responses = `responses.jsonl` lines whose `cell` is a finished cell.
- `list_runs(root="runs") -> list[Path]`: every subdir containing `run.json`; others skipped silently.

## 6. Execution (`sweep.py`)

### 6.1 Main loop
```
calibrate once (thermal.calibrate) with the first cell's model, profile "baseline", c = min level.
for stage in run.stages:
    if stage.cells empty: materialize (plan.materialize(stage, run)), save run.json
    for cell in stage.cells not in done:
        base  = omlx.prepare_base(...)
        cache = runs/<run_id>/cache/<cell_id>/ (mkdir)
        server.start(...); wait_ready; settings_check (§4.4); model = pick_model; warm-up stream_one("Say OK.", 16)
        gate (thermal.gate, unchanged)
        run_cell
        finally: server.stop(); rmtree(base); rmtree(cache)
        write cells/<cell_id>.json
    stage.status = "done"; save run.json
runstore.finish(run)  -> report + plots + dashboard
```
Resume = same loop; `done` = ids present in `cells/`. Remove `responses.jsonl` lines of unfinished cells on
resume (existing logic at old `main`, "drop responses of unfinished cells").

### 6.2 `run_cell` record additions (keep all existing keys)
`stage, model, profile, workload, scored, settings_check`,
`gpu: {"freq_mean", "freq_min", "util_mean"}` (from `Thermal.window` samples; `None` if no samples),
`requests[*]` add `pid` and, for prefix, `group`, `turn`, `warm` (§7.3).

### 6.3 `Thermal._read`
`gpu_usage` is `[freq_MHz, util_0_to_1]`. Store both: `"gpu_freq": u[0], "gpu_util": u[1]` when
`isinstance(u, list) and len(u) >= 2`, else `None`. Also store `gpu_freq` in `thermal.samples` as a 3rd element:
`[t, gpu_temp, gpu_freq]`.

### 6.4 Progress UI
Keep the three rows (`Overall`, `Thermal`, cell). Cell row description:
`f"{stage} · {model}/{profile} · C={c} · t{trial}"`. Quality stage info shows live `IF loose NN%`.

## 7. Workloads (`workload.py`)

### 7.1 `ifbench`
Prompt = `prompts[pid]`, single user message. Same as old quality path, minus scoring when `scored = false`.
Responses of unscored cells are **not** written to `responses.jsonl`.

### 7.2 `synthetic`
Kept only for the heater. Not selectable from CLI.

### 7.3 `prefix`
Deterministic from `seed`:
- **Document**: concatenate IFBench prompts in sorted-pid order, separated by `"\n\n"`, until
  `len(doc) >= 16000` chars. Different groups use different start offsets in that order
  (`group * 50` pids) so groups do not share a prefix with each other.
- **Questions**: fixed list in code, 6 items, e.g. `"Summarize section 3 in two sentences."` …
- **Group** = one document + 6 turns. Turn `k` messages:
  `system = doc`, then for `j < k`: `user = q[j]`, `assistant = <text returned at turn j>`, then `user = q[k]`.
- Turns of one group run **sequentially** (turn k needs turn k-1's text). Groups run in parallel up to `c`.
- Number of groups per cell = `max(c, 2)`. `max_tokens` for prefix = `--prefix-max-tokens` (default 256).
- Per request record: `group`, `turn`, `warm = turn > 0`.
- `stream_one(..., messages=None)`: if `messages` given, send it instead of the single user message.
  `jobs` for prefix cells = `[[f"g{g}", 0] for g in range(groups)]`; the group runner executes the 6 turns.

## 8. Analysis and output

### 8.1 Grouping key
All speed statistics group by `(model, profile, workload)` instead of `variant`. Row label
`f"{model}"` if profile is `baseline`, else `f"{model}/{profile}"`. Existing functions take lists of cells;
filter before calling. Do not change their math.

### 8.2 Quality
- Source: `responses.jsonl` rows with `score`, from `stage == "quality"` cells only.
- Per (model, profile): IF loose and strict, mean + bootstrap CI over prompts (existing `quality_summary`).
- Delete `quality_by_config` and the `IF loose @config` column.
- `paired(...)` comparisons, same code: every `kv*` profile vs `baseline` of the same model; every model vs
  the first model in `models.yaml`; `oq4e-mtp` vs `oq4e`.
- A speed row takes the quality of `(model, profile)`; if absent, of `(model, "baseline")` **only if** the
  profile has no `model_settings`. Otherwise `-`.

### 8.3 Cost and throttling (computed at report time, never stored in cells)
- `cost_per_M = price_kwh / (tok_per_j * 3.6e6) * 1e6`. Column `€/Mtok` (symbol from currency: EUR→€,
  USD→$, else code) right of `tok/J`. Header suffix ` (est.)` when `pricing.estimate`.
- Pricing resolution in `pricing.resolve(args, pricing_yaml) -> dict`:
  `--price` given → `{price_kwh, currency: --currency or yaml currency, source: "user", estimate: false}`;
  else region `--region` or `default_region` → yaml entry with `estimate: true`.
  `class PriceSource` with `get(region) -> dict`; implementations `StaticTable` (used) and `WebSource`
  (raises `NotImplementedError`). `--price-source static|web`, default `static`.
- Throttled: for cells with the same `c` and `workload`, `median = median(freq_mean)` of the others;
  flag if `freq_mean < 0.95 * median`. Report column `Thr` = `⚠` or blank. Legend line:
  `"⚠ = GPU freq > 5% below median at same C (hint only; decode is bandwidth-bound)"`.

### 8.4 `report.py` / `plots.py`
- Speed table: one per (model, profile) of workload `ifbench`; add columns `€/Mtok`, `GHz`, `Util`, `Thr`.
- Prefix table: per (model, profile, c): `cold TTFT` (turn 0 mean), `warm TTFT` (turn>0 mean, CI),
  `speedup = cold/warm` with `boot_ratio` CI, `tok/s`, `€/Mtok`.
- Trade-off table: columns `Config, IF loose [CI], Total tok/s, Per-req tok/s, p95 lat, €/Mtok, Pareto, Role`.
- Verdict adds: `Cheapest €/Mtok` (eligible configs, §existing eligibility) and `Best prefix profile`
  (highest warm-TTFT speedup whose CI lower bound > 1).
- Plots: every `"*"` marker (old lines with `"-o" if … else "*"` and `fmt="*"`) → `marker="o"`,
  `markerfacecolor="none"`, `markeredgewidth=2`, `ms=10`. Add a `€/Mtok vs C` panel to `graphs.png`.
  `tradeoff.png`: quality y-axis uses per-(model, profile) value as a horizontal line per series.
  Temperature panel: GPU freq on a twin y-axis, thin dotted line, same color.

### 8.5 `finish(run)`
Report to console → `summary.txt` (existing record trick) → `graphs.png`, `tradeoff.png` →
`dashboard.build("runs")`. `open` behavior unchanged, plus open `runs/index.html`.

## 9. CLI (`cli.py`)

```
python -m bench run       [--preset default|exhaustive] [--models a,b] [--profiles p,q] [--levels 1,2,4]
                          [--trials 3] [--samples 10] [--quality-c 1] [--no-quality] [--workload ifbench|prefix]
                          [--prefix-max-tokens 256] [--max-tokens 2000] [--min-requests 10] [--rounds 2]
                          [--temperature 0.6] [--top-p 0.95] [--seed 1234]
                          [--temp-band auto] [--no-thermal] [--calib-max 420] [--preheat-floor 50]
                          [--heat-max 600] [--cool-max 900] [--cooldown 30]
                          [--ratio 0.5] [--tie-margin 0.05]
                          [--price X] [--currency EUR] [--region NL] [--price-source static]
                          [--port 8000] [--api-key K] [--ready-timeout 240]
                          [--models-file models.yaml] [--pricing-file pricing.yaml]
                          [--out-dir runs/<run_id>] [--no-open] [--dry-run] [--yes]
python -m bench resume    DIR [--api-key K] [--port P] [--no-open]
python -m bench report    DIR [--price X] [--currency C] [--region R] [--ratio R] [--tie-margin M] [--no-open]
python -m bench rescore   DIR
python -m bench dashboard [--root runs] [--no-open]
```
- Defaults shown are the defaults. `--models` default = all in `models.yaml`. `--profiles` default `baseline`.
- `--preset exhaustive` ignores `--profiles`, `--levels`, `--workload`; uses `presets.exhaustive.stages`.
- `run` prints the plan (stage, cells, requests, estimated time) then asks `Proceed? [y/N]` unless `--yes`.
  `--dry-run` prints and exits 0 **before** preflight, IFBench clone, model download, or server start.
- Estimate per cell = `30 s start + 60 s gate + len(jobs) / c * max_tokens / 40 tok/s` for ifbench,
  `groups/c * 6 * (prefix_max_tokens / 40 + 2)` for prefix. Print total as `~Hh MMm`.
- `report` with overrides recomputes everything, writes outputs, never modifies `run.json`/cells.
- `resume` reuses `run.json["args"]`; only `--api-key`, `--port`, `--no-open` may be overridden.
- API key resolution: `--api-key` → `$OMLX_API_KEY` → `config.omlx_settings_key()`.

## 10. Dashboard (`dashboard.py`, `dashboard_template.html`)

- `build(root) -> Path`: for each run in `list_runs(root)`, `load_run`, compute the same derived rows as
  `report.py` (reuse functions; do not duplicate math) → JSON:
  `{"runs": [{"run_id", "started", "host", "pricing", "models", "profiles", "rows": [...], "quality": [...],
  "prefix": [...], "thermal": {cell_id: samples}, "recommendations": {...}}]}`.
- Template: single HTML file. Plotly from `https://cdn.jsdelivr.net/npm/plotly.js-dist-min@2/plotly.min.js`.
  Data injected as `<script id="data" type="application/json">…</script>`; replace the literal placeholder
  `/*__DATA__*/`. Escape `</` as `<\/` in the JSON string.
- UI:
  - Left: checkbox list of runs, then models, then profiles (derived from selected runs). Default: newest run, all.
  - Tabs: `Speed` (total tok/s and per-req tok/s vs C, CI error bars), `Cost` (€/Mtok vs C), `Quality`
    (IF loose per model/profile, CI bars), `Prefix` (cold vs warm TTFT), `Thermal` (temp + freq vs time,
    per selected cell), `Trade-off` (IF loose vs total tok/s scatter, Pareto points highlighted),
    `Table` (all rows, click header to sort), `Recommendations` (verdict lines of selected runs).
  - Series color = model color; profile = line dash (`baseline` solid, others cycle `dash, dot, dashdot`).
  - Single-point series: hollow circle marker, same rule as §8.4.
  - Recommended points: ring marker + label on `Speed` and `Trade-off`.
- Runs from different hosts or `omlx_version` can be selected together; show a warning banner listing the
  differing fields.
